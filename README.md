# thoth

[![License: GPL v3](https://img.shields.io/badge/License-GPLv3-blue.svg)](https://www.gnu.org/licenses/gpl-3.0)
![Platforms](https://img.shields.io/badge/platforms-Linux%20%7C%20macOS%20%7C%20Windows%20%7C%20ARHeOS-lightgrey)
![Language](https://img.shields.io/badge/language-C11-informational)

Простой консольный текстовый редактор в духе `nano` и `mcedit`.
Работает нативно на **Linux**, **macOS**, **Windows (MINGW64)** и собирается
под **ARHEOS** (хобби-ОС для x86) через тонкий слой платформенной абстракции.

Ядро редактора полностью портативно: оно общается с внешним миром через
интерфейс `tp_*` (см. `thoth_platform.h`), который скрывает терминальный
ввод-вывод, файловые операции, декодирование клавиатуры, работу со временем
и буфер обмена за несколькими функциями. В комплекте две реализации:

- `platform_posix.c` — Linux / macOS / Windows (MINGW64) (ANSI-терминал, `termios`)
- `platform_arheos.c` — ARHEOS (системные вызовы ядра, драйвер клавиатуры на скан-кодах)

## Возможности

- **Архитектура piece-table.** Содержимое файла остаётся на диске, редактор держит только индекс `line_offset[]` плюс разрежённый список изменённых строк (`dirty[]`). Прямо-адресуемый кэш на 512 слотов хранит «чистые» строки вокруг курсора. Открытие 100-мегабайтного лога не съедает ОЗУ: память растёт с **числом отредактированных строк**, а не с размером файла.
- **Undo / redo.** История правок — 32 снапшота (приблизительный бюджет памяти 4 МБ, самый старый вытесняется при переполнении). `Ctrl+Z` / `Ctrl+Y`. Каждый снапшот хранит `line_offset[]`, `dirty[]`, позицию курсора и скролл; сложность восстановления — O(строк в файле), но количество правок, которые можно откатить, ограничено только бюджетом памяти.
- **Выделение (mcedit-style).** `F3` ставит метку в текущей позиции, движениями курсора растягивается диапазон; повторный `F3` фиксирует конец. `ESC` снимает выделение. Выделенный фрагмент подсвечивается инверсией фона (чёрный текст на светло-серой подложке — работает и в ARHeOS-консоли, и в POSIX-терминалах).
- **Блочные операции (mcedit-style).** При зафиксированном выделении (`SEL_LOCKED`):
  - `F5` — скопировать блок в позицию курсора,
  - `F6` — переместить блок в позицию курсора,
  - `F8` — удалить блок.
  Курсор может быть перемещён куда угодно до вызова F5/F6/F8; вставка идёт в текущую позицию курсора, а не в конец выделения.
- **Системный буфер обмена.** `Ctrl+C` / `Ctrl+X` / `Ctrl+V` работают с глобальным clipboard ОС и переживают завершение thoth:
  - **Windows** — Win32 API (`OpenClipboard` / `SetClipboardData` с `CF_UNICODETEXT`);
  - **macOS** — `pbcopy` / `pbpaste`;
  - **Linux** — `wl-copy` / `wl-paste` (Wayland) или `xclip` (X11); выбор автоматический по `XDG_SESSION_TYPE`;
  - **ARHEOS** — системный вызов `SYS_CLIPBOARD`, буфер per-TTY (все процессы одного терминала делят один clipboard).
- **Command на macOS.** Бэкенд `platform_posix.c` активирует Kitty keyboard protocol (`ESC[>1u` в `tp_init`). Терминалы, поддерживающие CSI-u, присылают `Cmd+C` / `Cmd+V` / `Cmd+X` / `Cmd+Z` / `Cmd+Y` как отдельные события с флагом `cmd`; редактор обрабатывает их наравне с `Ctrl+…`. Работает в Kitty, WezTerm, foot, Alacritty 0.13+ из коробки; в iTerm2 — после включения `Enable "CSI u" mode` и переназначения `⌘C`/`⌘V`/`⌘X` на пропуск в приложение. В Terminal.app Cmd-комбинации перехватываются самим эмулятором, используйте `Ctrl+C/V/X`.
- **Bracketed paste.** Если терминал отправляет маркеры `ESC[200~ … ESC[201~`, вставка приходит из `tp_read_event()` одним событием-маркером (`EV_CHAR` с `cp == 0xFFFF0000u`). Ядро забирает содержимое через `tp_take_paste_buf()` и обрабатывает как единую операцию: выделение корректно заменяется, undo откатывает всю вставку за один шаг. На терминалах без bracketed paste ввод идёт посимвольно.
- **Любой размер файла**, который влезает на диск, при условии `line_count < 2^32`.
- **Полная поддержка UTF-8**: ввод, навигация и отрисовка. Курсор никогда не попадает в середину многобайтного codepoint'а. Копирование в clipboard режет строки по границам codepoint'ов.
- **Развёртка табов** в 4 визуальные ячейки. Табы считаются за 4 колонки при прокрутке и горизонтальном позиционировании.
- **Горизонтальная и вертикальная прокрутка** с автоподстройкой. Вертикальный скроллбар справа, если файл длиннее экрана.
- **Переключение раскладки** На ARHEOS Alt+Shift/Ctrl+Shift (комбинация настраивается в конфиге ОС) переключает раскладку, keymap прозрачно перезагружается.
- **Обработка `SIGWINCH`** на POSIX: изменение размера окна терминала перерисовывает интерфейс с сохранением позиции курсора. `SIGINT`/`SIGTERM`/`SIGHUP` корректно восстанавливают `termios` перед выходом.
- **Атомарное сохранение** через `<file>.tmp` + `rename()`. На ARHEOS VFS-слой реализует `rename()` как copy+unlink через хук `fs_driver_api_t::rename`, если драйвер его поддерживает (fast-path для EXT2 и FAT12).
- **Встроенный экран помощи** (`F1`).

## Клавиши

### Файл и выход

| Клавиша          | Действие                                              |
| ---------------- | ----------------------------------------------------- |
| `F1`             | Помощь                                                |
| `F2` / `Ctrl+S`  | Сохранить                                             |
| `F10` / `Ctrl+Q` | Выйти (спросит подтверждение, если есть правки)       |

### Движение курсора

| Клавиша          | Действие                                              |
| ---------------- | ----------------------------------------------------- |
| `Стрелки`        | Движение курсора                                      |
| `Home` / `End`   | Начало / конец строки                                 |
| `PgUp` / `PgDn`  | Страница вверх / вниз                                 |

### Редактирование

| Клавиша          | Действие                                              |
| ---------------- | ----------------------------------------------------- |
| `Del`            | Удалить символ под курсором                           |
| `Backspace`      | Удалить символ перед курсором                         |
| `Enter`          | Разбить строку                                        |
| `Tab`            | Вставить таб (4 пробела)                              |

### Undo / Redo

| Клавиша                    | Действие                                |
| -------------------------- | --------------------------------------- |
| `Ctrl+Z` / `Cmd+Z` (macOS) | Отменить последнюю правку               |
| `Ctrl+Y` / `Cmd+Y` (macOS) | Повторить отменённую правку             |

> Раньше undo/redo висело на `F5`/`F6`. Теперь эти клавиши заняты
> mcedit-style блочными операциями — см. ниже.

### Выделение и блочные операции

| Клавиша                    | Действие                                        |
| -------------------------- | ----------------------------------------------- |
| `F3` (1-е нажатие)         | Поставить метку, выделение в режиме `TRACKING`  |
| `F3` (2-е нажатие)         | Зафиксировать конец, выделение в режиме `LOCKED`|
| `ESC`                      | Снять выделение                                 |
| `F5` (только в `LOCKED`)   | Скопировать блок в текущую позицию курсора      |
| `F6` (только в `LOCKED`)   | Переместить блок в текущую позицию курсора      |
| `F8` (в `TRACKING`/`LOCKED`) | Удалить выделенный блок                       |

> `F5` — это **внутренняя** операция mcedit: скопировать блок в позицию
> курсора внутри файла. Системный буфер обмена она не трогает. Для
> копирования в clipboard используйте `Ctrl+C` / `Cmd+C`.

### Буфер обмена

| Клавиша                       | Действие                                       |
| ----------------------------- | ---------------------------------------------- |
| `Ctrl+C` / `Cmd+C` (macOS)    | Скопировать выделение в системный буфер обмена |
| `Ctrl+X` / `Cmd+X` (macOS)    | Скопировать выделение в буфер обмена и удалить |
| `Ctrl+V` / `Cmd+V` (macOS)    | Вставить из буфера обмена (заменяет выделение) |

**macOS:**

- **iTerm2** — Preferences → Profiles → Keys → Key Mappings: переназначьте `⌘C`/`⌘V`/`⌘X` так, чтобы они доходили до приложения (`Send Keystroke`). Там же Profiles → Terminal → **`Enable "CSI u" mode`**.
- **Kitty / WezTerm / foot / Alacritty 0.13+** — CSI-u включён по умолчанию, thoth активирует режим сам.
- **Terminal.app** — не поддерживает CSI-u. `Cmd`-комбинации перехватываются эмулятором и до приложения не доходят. Работает только `Ctrl+C/V/X`.

## Сборка под Linux / macOS

Нужен только компилятор C11 и стандартная библиотека C.
`termios`, `select`, `ioctl` и `signal` — часть POSIX. На macOS
дополнительно требуются `cfmakeraw()` (есть с 10.5) и
`clock_gettime(CLOCK_MONOTONIC)` (есть с 10.12).

**Зависимости для буфера обмена:**

| Платформа        | Утилиты / API                                         | Пакет                 |
| ---------------- | ----------------------------------------------------- | --------------------- |
| macOS            | `pbcopy` / `pbpaste`                                  | встроены в систему    |
| Linux / Wayland  | `wl-copy` / `wl-paste`                                | `wl-clipboard`        |
| Linux / X11      | `xclip -selection clipboard`                          | `xclip`               |
| Windows          | Win32 API (`OpenClipboard` / `SetClipboardData`)      | —                     |

При отсутствии утилиты на Linux операции с буфером возвращают ошибку (`Copy failed` / `Paste failed`), но редактор продолжает работать. На macOS и Windows никаких внешних зависимостей нет.

1. Убедитесь, что `ARHEOS_OS` в `include/thoth.h` **закомментирован**:

```c
/* #define ARHEOS_OS */
```

2. Сборка:

- Сборка под ARHEOS происходит силами единого скрипта.
- Для сборки под Linux/Mac OS достаточно использовать стандартный Makefile:

```bash
make
```

Либо вручную: 

```bash
cc -O2 -g -Wall -Wextra -std=c11 -o thoth thoth.c platform_posix.c
```


3. Запуск:

```bash
./thoth /path/to/file.txt
```

Или просто
```bash
./thoth
```

## Сборка под Windows (MINGW64)

1. Установить в MINGW64 нужные пакеты:

```bash
pacman -S mingw-w64-ucrt-x86_64-pkg-config mingw-w64-ucrt-x86_64-sigutils
```

2. Убедиться, что установлен sigutils для поддержки termios.h:

```bash
pkg-config --cflags sigutils
```

3. Выполнить сборку в директории проекта:

```bash
make
```

4. Запуск:

Полученный исполняеемый файл thoth.exe запустить в консоли

```bash
./thoth.exe
```

**Буфер обмена на Windows** реализован через Win32 API (`OpenClipboard` / `SetClipboardData` с `CF_UNICODETEXT`). Буфер разделяется с другими приложениями Windows и сохраняется после выхода из thoth.

## Сборка под ARHEOS

Этот репозиторий — канонический источник внутрисистемного thoth.elf - основного консольного текстового редактора.
В основном дереве ARHeOS он живёт по пути

```bash
userspace/system procs/thoth/
```

1. Убедитесь, что в include/thoth.h ARHEOS_OS **раскомментирован**:

```c
#define ARHEOS_OS
```

2. Редактор собирается теми же freestanding-флагами, что и остальные userspace-программы ОС:

```bash
$CC $USER_CCFLAGS_ELF -c thoth.c           -o bin/u_thoth.o
$CC $USER_CCFLAGS_ELF -c platform_arheos.c -o bin/u_thoth_platform.o
```

3. Линковка в PIE ELF:

```bash
$LD $USER_LDFLAGS_ELF \
    bin/u_std_elf.o bin/u_memory_elf.o \
    bin/u_thoth.o bin/u_thoth_platform.o \
    -o bin/thoth.elf
```

4. Далее thoth.elf кладется в целевую файловую систему (FAT12-флоппи или EXT2-HDD — обе поддерживаются) и запускается из шелла Сехмет:

```bash
> thoth filename.txt
```

## Требования внутри ARHEOS

platform_arheos.c линкуется с:

- include/ustd.h — обёртки над системными вызовами (u_write, u_read,
- u_kbd_set_mode, u_locale_get, u_locale_get_keymap,
- u_get_console_geometry, …)

- include/umemory.h — malloc / free

- include-kernel/locale_types.h — locale_keymap_t

Для буфера обмена используется системный вызов SYS_CLIPBOARD (номер 59, см. userspace/include/syscall.h).
Реализация — в kconsole.c (kernel_clipboard_*) плюс обработчик systemcall_clipboard в syscalls.c. Буфер per-TTY: все процессы, привязанные к одному tty_t, видят один clipboard.

Всё это есть в дереве ARHeOS, ничего дополнительного не нужно.

В thoth.c нет ни одного #ifdef про платформу. Всё, что зависит от ОС, вынесено в tp_* (см. thoth_platform.h). Чтобы портировать редактор на новую ОС, достаточно реализовать этот интерфейс — ядро трогать не нужно.

## Интерфейс платформы (для портирования)

thoth_platform.h определяет:

```c
int      tp_init(void);
void     tp_shutdown(void);

int      tp_write(int fd, const void *buf, uint32_t n);
int      tp_open  (const char *path, uint32_t flags);
int      tp_close (int fd);
int      tp_seek  (int fd, uint32_t pos);
int      tp_read  (int fd, void *buf, uint32_t n);
int      tp_unlink(const char *path);
int      tp_rename(const char *oldpath, const char *newpath);

void     tp_clear_screen(void);
void     tp_geometry(uint32_t *cols, uint32_t *rows,
                     uint32_t *cw,   uint32_t *ch);

bool          tp_kbhit(void);
thoth_event_t tp_read_event(void);   //EV_CHAR / EV_KEY / EV_NONE

void     tp_poll_locale(void);
uint32_t tp_ticks(void);             //100 Гц
void     tp_yield(void);
void     tp_exit(void);
bool     tp_resized(void);

//Системный буфер обмена
int      tp_clipboard_set(const void *buf, uint32_t size);
uint32_t tp_clipboard_size(void);
int      tp_clipboard_get(void *buf, uint32_t max);
void     tp_clipboard_clear(void);

//Bracketed paste: забрать накопленный в бэкенде блок
bool     tp_take_paste_buf(const uint8_t **buf, uint32_t *len);
```

tp_read_event() переводит то, что предоставляет ОС (скан-коды на ARHEOS, ANSI-escape-последовательности на POSIX), в небольшой набор семантических событий:

```c
typedef struct {
    thoth_event_kind_t kind;   //EV_CHAR | EV_KEY | EV_NONE
    uint32_t           cp;     //EV_CHAR: Unicode codepoint
    thoth_key_t        key;    //EV_KEY:  TK_ENTER, TK_LEFT, TK_F1, …
    bool               ctrl;   //EV_CHAR: Ctrl удерживается
    bool               cmd;    //EV_CHAR: Command (macOS) / Super удерживается
} thoth_event_t;
```

Ядро редактора никогда не видит ни скан-кодов, ни escape-последовательностей. Поле `cmd` заполняется бэкендом `platform_posix.c` при получении CSI-u (`ESC [ key ; mods u`) с битом `super`. На ARHEOS `cmd` всегда `false`.

**Bracketed paste.** Если бэкенд распознаёт `ESC[200~ … ESC[201~`, он возвращает из `tp_read_event()` одно событие-маркер `EV_CHAR` c `cp == 0xFFFF0000u`. Ядро забирает содержимое через `tp_take_paste_buf()` и обрабатывает как единую вставку (с одним undo-снапшотом). Бэкенды без поддержки bracketed paste (включая ARHEOS) реализуют `tp_take_paste_buf` как заглушку, возвращающую `false`; вставка тогда идёт посимвольно.

**tp_clipboard_*** — системный буфер обмена:

- **POSIX**: `platform_posix.c` общается с системным clipboard через `popen()` к платформенной утилите (`pbcopy`/`pbpaste` на macOS, `wl-copy`/`wl-paste` на Wayland, `xclip` на X11). Размер буфера кэшируется между вызовами; `tp_clipboard_size()` возвращает сохранённый размер без обращения к внешней утилите.
- **ARHEOS**: kernel heap через syscall (лимит 1 МБ, per-TTY разделение).

## Ограничения

- Undo / redo — снапшот-базированный. Глубина истории 32 снапшота, суммарный бюджет 4 МБ. На очень больших файлах (миллионы строк) старые снапшоты вытесняются раньше, чем пользователь успеет ими воспользоваться. Правка в 1 символ создаёт полный снапшот индекса. Для файлов, где line_count * 4 > 4 МБ / 32, история будет эффективно одноуровневой.

- Буфер обмена ограничен 1 МБ (обрезка при copy). Интегрирован с системным clipboard на всех платформах. На Linux требуется установленная утилита `wl-clipboard` (Wayland) или `xclip` (X11); при их отсутствии операции с буфером возвращают ошибку, но редактор продолжает работать. На macOS `pbcopy`/`pbpaste` есть всегда, на Windows используется Win32 API.

- На macOS поддержка `Cmd+…` зависит от терминала: CSI-u работает в Kitty / WezTerm / foot / Alacritty 0.13+ «из коробки», в iTerm2 требует явного включения (`Enable "CSI u" mode` + переназначение `⌘C`/`⌘V`/`⌘X`), в Terminal.app невозможна. Универсальный fallback — `Ctrl+C/V/X`.

- Bracketed paste обрабатывается только на POSIX и только если терминал отправляет маркеры `ESC[200~`/`ESC[201~`. Иначе вставка идёт посимвольно, и каждая вставленная буква создаёт отдельный undo-снапшот.

- Выделение — только построчное (линейный диапазон от (anchor_line, anchor_byte) до (end_line, end_byte)). Блочное (прямоугольное) выделение, как в редакторах для кода, не реализовано.

- Нет поиска и замены. В планах.

- Нет мыши. ANSI SGR-мышь портативна; тоже в планах.

- line_offset[] — uint32_t. Файлы до 4 ГБ. Больше — потребуется индекс на uint64_t, что удвоит память под индекс.

- MAX_LINE_LEN = 64 КБ. Строка длиннее будет обрезана при загрузке. Обычные текстовые файлы в это не упираются; минифицированный JS или base64-блоки — упрутся.

- Вставка / удаление в середине файла на 10 млн строк перемещает с помощью memmove хвост line_offset[] — около 40 МБ на каждый Enter. Правки в начале или конце (типичный сценарий) остаются мгновенными.

- Сохранение использует соседний <file>.tmp. Нужны права на запись в директорию файла и примерно удвоенное свободное место на диске. На флоппи 1.44 МБ максимальный сохраняемый файл — около 700 КБ.

- Обработка resize — только на POSIX. У ARHEOS, на данный момент, фиксированный размер фреймбуфера.

## Планы

- Инкрементальный поиск Ctrl+F, замена Ctrl+H.

- Мышь: клик — поставить курсор, колесо — прокрутка, drag скроллбара.

- Подсветка синтаксиса (построчная, без полноценного токенайзера).

- Аналог SIGWINCH для ARHEOS через событие ядра.

- Прямоугольное (block) выделение, как в vim/mcedit (сейчас — только линейное).

- Undo/redo на основе piece-table (тройки (line_no, old_text, new_text)) вместо полных снапшотов — экономит память на больших файлах.

- Группировка последовательных однобуквенных правок в один undo-снапшот (сейчас каждая вставка символа — отдельный шаг истории).

- Опциональная поддержка Meta на macOS (`ESC+letter` → Alt) для терминалов без CSI-u.
